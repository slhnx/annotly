<objective>
Build the dedicated project settings view at `/dashboard/projects/[projectId]/settings` with dirty-state tracking, review link/access controls, and confirmed project deletion.

Purpose: Allow project owners to safely update project details, control shareable review link access, and delete projects with deliberate confirmation while preventing accidental loss of unsaved edits.
Output: `/dashboard/projects/[projectId]/settings` route, `useUnsavedChanges` hook, and modular `project-settings/*` cards.
</objective>

<tasks>
<task id="1" name="Create useUnsavedChanges hook and ProjectGeneralSettingsCard">
Create `features/projects/hooks/use-unsaved-changes.ts` (handling `beforeunload` when dirty and tracking dirty state against saved baseline) and `features/projects/components/project-settings/project-general-settings-card.tsx` with shadcn `Card`, `Input`, `Textarea`, `Select`, "Unsaved changes" `Badge`, "Discard" reset button, and "Save Changes" submit button wired to `updateProjectAction`.
</task>

<task id="2" name="Create ProjectReviewAccessCard and ProjectDangerZoneCard">
Create:
- `features/projects/components/project-settings/project-review-access-card.tsx`: copy shareable review link button, review link access selector (`public` active vs `paused`), and "Regenerate Review Link" action with confirmation.
- `features/projects/components/project-settings/project-danger-zone-card.tsx`: destructive-tinted `Card` that opens `DeleteProjectDialog` and redirects to `/dashboard/projects` after deletion.
</task>

<task id="3" name="Create /dashboard/projects/[projectId]/settings page">
Create `app/(dashboard)/dashboard/projects/[projectId]/settings/page.tsx` as a Server Component that loads the project via `getProjectByIdAction` (calling `notFound()` if missing or unauthorized) and renders the header tabs/navigation between Overview and Settings alongside the three settings cards.
</task>
</tasks>
