<objective>
Build a dedicated, accessible project creation flow UI at `/dashboard/projects/new` (while preserving the quick-create dialog on `/dashboard/projects`) consistent with `DESIGN.md`, `AGENTS.md`, and the semantic shadcn token system.

Purpose: Give users a clear, guided setup experience that explains target URL requirements, provides instant and server-authoritative field validation, and transitions smoothly to the newly created project's detail view.
Output: `/dashboard/projects/new` page, modular `NewProjectForm` and `UrlRequirementsCard` components, and updated entry links.
</objective>

<tasks>
<task id="1" name="Create URL requirements & setup guidance card">
Create `features/projects/components/url-requirements-card.tsx` using shadcn `Card`, `Badge`, and semantic tokens (`bg-card`, `text-foreground`, `text-muted-foreground`, `border-border`) explaining:
- Publicly reachable `https://` or `http://` website URLs (auto-normalized if protocol is omitted)
- Staging, preview (Vercel/Netlify), and production domains supported
- Zero-install live canvas behavior (no script tag or browser extension required)
</task>

<task id="2" name="Build modular NewProjectForm component">
Create `features/projects/components/new-project-form.tsx` reusing `ProjectFormFields` and `useProjectForm`, adding live normalized-URL preview, field-level validation feedback, recoverable `Alert variant="destructive"` banner, submitting state, and navigation to `/dashboard/projects/[projectId]` on creation success.
</task>

<task id="3" name="Create /dashboard/projects/new route and wire navigation">
Create `app/(dashboard)/dashboard/projects/new/page.tsx` as a Server Component that verifies authentication (`requireAuth`) and renders the header, breadcrumb trail, `NewProjectForm`, and `UrlRequirementsCard`. Update dashboard "New Project" entry points where appropriate so users can reach the dedicated flow or quick modal seamlessly.
</task>
</tasks>
