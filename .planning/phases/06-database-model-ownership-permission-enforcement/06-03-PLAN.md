<objective>
Implement the typed Data Access Layer for Canvases, Annotations, and Threaded Replies (Plan 06-03).

Purpose: Provide secure, authorized, and validated data access services for the zero-install review canvas and visual commenting engine, maintaining transactional consistency and metric rollups.
Output: `CanvasService`, `AnnotationService`, shared Zod input schemas, domain types, and integration test suite `tests/data-access-layer.test.ts`.
</objective>

<tasks>
<task id="1" name="Implement Canvas data access types, schemas, and CanvasService">
Create `features/reviews/types/index.ts`, `features/reviews/schemas/canvas.schema.ts`, and `features/reviews/services/canvas-service.ts`:
- `getCanvasByToken(token)`: Retrieves canvas for public review, checks paused state, and exposes safe public project metadata (redacting private owner info).
- `getProjectCanvases(userId, projectId)`: Retrieves all canvases for a project with owner verification.
- `updateCanvasAccess(userId, canvasId, reviewAccess)`: Toggles public/paused state with owner authorization.
</task>

<task id="2" name="Implement Annotation schemas, types, and AnnotationService">
Create `features/annotations/types/index.ts`, `features/annotations/schemas/annotation.schema.ts`, and `features/annotations/services/annotation-service.ts`:
- Zod schemas validating percentage coordinates (`offsetX`, `offsetY` between 0 and 100), device dimensions, selector snippets, and guest/registered identity.
- `createAnnotation(input)`: Validates canvas access, persists pin and device context, atomically increments project `totalComments` and `openComments`.
- `getCanvasAnnotations(canvasToken, filter)`: Retrieves annotations with ordered threaded replies, supporting `open`, `resolved`, or `all` filters.
- `updateAnnotationStatus(actor, annotationId, status)`: Resolves or re-opens annotation with owner or author permission, updating project metric rollups.
- `addReply(input)`: Adds threaded reply to annotation and updates project `lastActivityAt`.
- `deleteAnnotation(actor, annotationId)`: Deletes pin and cascades replies with owner/author authorization, decrementing project metrics.
</task>

<task id="3" name="Implement comprehensive Data Access Layer test suite">
Create `tests/data-access-layer.test.ts` testing:
- Canvas retrieval by public token and paused access enforcement
- Coordinate validation rejecting invalid offsets (<0% or >100%)
- Creation of annotations by both registered users and guest reviewers
- Threaded reply addition and ordering
- Status toggling (`open` -> `resolved` -> `open`) and atomic project metric rollups
- Authorization gates preventing unauthorized resolution or deletion
</task>
</tasks>
