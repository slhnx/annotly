<objective>
Document the system permission matrix and implement exhaustive adversarial security tests (Plan 06-04).

Purpose: Guarantee and verify tenant isolation, least-privilege public access, and authorization boundaries across all project and review operations before opening visual canvas review routes.
Output: `docs/permission-matrix.md` and adversarial test suite `tests/permission-adversarial.test.ts`.
</objective>

<tasks>
<task id="1" name="Document formal Role and Permission Matrix">
Create `docs/permission-matrix.md` defining capabilities and constraints across:
- Roles: Project Owner, Authenticated Collaborator, Public Guest Reviewer, and Anonymous/Intruder
- Entities: Project, Canvas, Annotation, AnnotationReply
- Access Matrix: Read, Create, Update, Delete, Resolve, and Access Toggle permissions
- Security Guarantees: Least-privilege data disclosure, token randomness, tenant isolation, and leak prevention
</task>

<task id="2" name="Implement adversarial security and authorization test suite">
Create `tests/permission-adversarial.test.ts` testing:
- Cross-tenant read: User B querying User A's projects and canvases
- Cross-tenant write: User B attempting to edit, rename, or delete User A's project
- Guessed IDs and malformed tokens: Querying non-existent, empty, or malicious strings
- Unauthorized annotation mutation: Intruders attempting to resolve or delete annotations
- Paused canvas enforcement: Attempting to bypass paused status to leave comments or replies
- Information disclosure audit: Ensuring public canvas queries never leak owner user ID, email, or other projects
</task>
</tasks>
